# Known limitations

- **Tutor** is the rule-based, clearly labelled "development tutor" unless a model is configured (`ANTHROPIC_API_KEY`, or `LLM_PROVIDER=openai` + `LLM_BASE_URL`). The model path (`server/services/llmEngine.ts`) is tested against a mock server that follows the documented request/response shapes; **a checker exists (`scripts/check-tutor.ts`) but it has not been run against a live model**, so answer quality and Tamil fluency are unmeasured. The model writes only the lesson steps, cites retrieved sources, and falls back to the rule-based lesson on any problem. The lesson is streamed: the model writes one step per line, each step is checked as it arrives, and step 1 is spoken while the rest is still being written (tested against a mock streaming server only; the real time-to-first-step depends on your provider and is unmeasured). While streaming, step 1 shows "Step 1" without the total, and the progress dots appear from step 2. If the stream breaks after step 1, the steps already taught are kept; if it breaks before any step, the built-in lesson is used without asking the model again.
- **OCR**: scanned or badly-encoded **textbook** PDFs are read with Tesseract (Tamil + English) in a background job; this needs `tesseract` and `poppler` installed (the Docker image has them). Tesseract's Tamil output is good but not perfect: expect occasional wrong letters and header debris, and it cannot read tables or diagrams. Photo text reading for **student uploads** still needs a configured model key. Student-uploaded scanned PDFs are not OCR'd.
- **Curriculum**: sample content only (published for Class 8; placeholders elsewhere). Not official Samacheer Kalvi text; needs review by qualified educators.
- **Database**: PostgreSQL (`DATABASE_URL`) for production and SQLite (`node:sqlite`, experimental) for development; the whole test suite runs on both. Single app instance only (in-memory rate limiter; OCR queue runs in-process). No schema migrations yet: tables are created if missing, and later schema changes will need migration scripts.
- **No SMS.** Email is built (reset, confirmation, guardian approval) but only tested against a mock Resend server and an in-process SMTP server, never a real provider. Guardian approval proves control of the guardian's mailbox, not who they are.
- **Test integrity** in a browser is limited (no proctoring); server timing and autosave are authoritative.
- **Voice** input (speech-to-text) always uses the browser's Speech API and is hidden when unsupported; Tamil recognition quality varies by browser and phone. Voice output uses Azure AI Speech when configured (tested against a mock of its REST API, not the live service), otherwise the browser voice.
- **Draft question generator** is maths-only; all generated questions need human review before publishing.
- **Accessibility**: automated axe checks pass; no manual screen-reader audit yet.
- **Uploads**: type/size/magic-byte checks, but no antivirus scanning. Files live on local disk or an S3-compatible bucket (`STORAGE_DRIVER`).
- No ESLint config; no CI pipeline.
- **Sign-up**: email confirmation is a reminder, not a gate: unconfirmed students can still sign in. Under-13 approval happens through the emailed guardian link (or the link code if no mail provider is set). Teacher and school-admin sign-ups are approved on the admin People screen (`/admin/people`), which also finds accounts, switches them off and helps people who are locked out (email link or one-time temporary password). Approval relies on the admin judging the details; nothing is verified automatically. The UI uses `/app`, not the `/student/...` route names from the master prompt.
- **Existing dev databases** created before the `pending` role was added must be deleted (`data/kavli.db`) so the new schema is created.
- **UI-preview mode** (`.env.production`) fakes the API in the browser; sign-ups there are kept for the tab only.
- **UI-preview mode** replays one recorded run (sample student, canned passing test, canned practice set and material answers); it does not grade or persist anything. It exists only to review screens without a backend.

## Class 8 textbook import (English, Tamil, Mathematics)

- **English (imported, partial):** 6 lessons from the Class 8 English textbook (Unit 1 and Unit 2: prose, poem, supplementary) are in `server/curriculum/class8-english.json`. The text we received from the Drive connector stops partway through Unit 3, so the rest of the book (Units 3–7 and the play) is **not** imported. Each lesson is a short excerpt with its source and starting page, shown in English only. Run `scripts/import-textbook.ts` again with a fuller extraction to add the rest.
- **Tamil, Class 8 (imported as a searchable class book, not as lessons):** the PDF's text layer is corrupted on essentially every page (measured: 4.6–10 malformed sequences per 100 Tamil characters, against 0–1.5 for OCR output). The importer detects that and OCRs the pages; all 192 pages were read (about 7 minutes). It is a Central-board-style edition, so page numbers and wording may differ from the Samacheer Kalvi print the students hold. It is available to the tutor for retrieval and to students in the reader; its 39 chapters are found automatically from the printed contents page (checked by eye against the pages, not by a teacher) and the tutor can be kept inside one chapter, but it has **not** been turned into authored step-by-step lessons. Some contents titles carry the unit name with them (for example "மொழி தமிழ்மொழி வாழ்த்து"), and a wrapped title is cut at its first line; an admin can correct titles and page ranges by hand. Retrieval is measured against 27 labelled questions (`eval/class8-tamil.questions.json`, run `npx tsx scripts/eval-retrieval.ts`): right page ranked first for 18 of 24 answerable questions (75%) and in the top 3 for 22 (92%), mean reciprocal rank 0.83; all 3 questions the book cannot answer correctly returned nothing. The labels were written by the developer from the OCR text, not by a teacher, and the set is small, so treat the figures as a regression guard, not a promise. Known misses: a Thirukkural chapter-title question and the national-song page.
- **Mathematics, Tamil medium (not imported):** the PDF has no text layer at all (scanned pages), so it also needs OCR of the original file.
- Files over 10 MB cannot be downloaded through the Drive connector and Drive is not reachable from the build environment, so the three PDFs (67 MB, 17 MB, 40 MB) must be attached to the chat or placed in the project folder.
- Textbook lessons are excerpts for learning and tutor grounding. They are not a replacement for the printed textbook. Check Tamil Nadu Textbook Corporation terms before publishing more than short excerpts.

- Slow/offline behaviour was tested with the browser offline switch only, not on real 2G/3G links; Tamil rendering was checked on desktop Chromium fonts, not on physical low-end Android devices.
- Side-by-side bilingual view relies on the existing "both languages" mode; no separate per-message toggle was added. The preview tutor remains canned.
- axe accessibility scan not run.

- Class books: scanned or garbled PDFs are OCR'd in the background (see above); until OCR finishes the tutor can use only the pages already read. Chapters come from the printed contents page ("title … page number"): a book without a readable contents page gets no chapter list (the admin can type one in), and page-number misreads are filtered but not repaired. Chapter-scoped tutoring is tested on synthetic books and spot-checked on the real Tamil book; it is not in the labelled retrieval set. Retrieval is lexical (BM25 over stemmed words plus Tamil character 3-grams, which tolerates word endings, split or joined words and small OCR errors), not semantic, so a question phrased with entirely different words than the book can still miss the right page. A question with three or more content words needs more than one matching word, so the tutor may say it cannot find something rather than guess. Each question takes about 0.2 s on a 192-page book (passages are rebuilt per question; cache them if many books are loaded). Hosting official textbooks requires the right to share them. The UI-preview (Vercel) build has no backend, so the book screens show an empty list there. The Anthropic-API tutor path does not yet attach book page links (only the built-in tutor does).

## Added in the production-hardening pass
- Diagrams are original drawings made for this project and have **not** been reviewed by a teacher. They are labelled as such in the app.
- Production bootstrap (`SEED_DEMO=0`) creates only the subject list, the real textbook lessons and the built-in practice questions. The built-in practice questions are included; teachers must add weekly tests.
- The first admin is created with `scripts/create-admin.ts`. Password reset works by email only when a mail provider is configured; without one, an admin must reset it.
- The Docker image was written but **not built** in the authoring environment (no Docker daemon). The production-only dependency install and the non-preview front-end build were run separately and work.
- The textbook PDF itself and its extracted text are not in the repository; test fixtures use sentences written for the tests.
